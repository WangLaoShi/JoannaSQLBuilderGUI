# JoannaSQLBuilderGUI

这是 SQL Joiner 的 Node 版本，GitHub 仓库名是 JoannaSQLBuilderGUI，当前版本 **1.1.3**。代码放在 `node_app/`。学生不需要安装 PHP。本机起一个服务，浏览器或安装包打开同一套拖拽画布，用它连接 MySQL，把 SELECT 查询搭出来再运行。

窗口标题仍显示 SQL Joiner。原来的 PHP 版本仍在 `app/`，说明见根目录的 `README.md`。协议是 GPL-3.0-or-later，见 `LICENSE`。

## 开发历史

版本号从 2026-10-18 起只写在 `node_app/package.json`。在此之前，功能版本号写在原 PHP 项目的提交说明里，从 1.0.0 一直加到 1.117.0。两边的号码不是同一条序列：1.1.1 是这个 Node 版本自己的号。

### 2026-04-07　原项目 1.0.0

起点是 [webofmarius/SQLJoiner](https://github.com/webofmarius/SQLJoiner)。PHP 8 内置服务器，可选 Electron。画布上拖表、在字段之间连线，拼出 SELECT。连接类型有 INNER、LEFT、RIGHT、FULL OUTER、CROSS。SELECT、WHERE、GROUP BY、HAVING、ORDER BY 可以可视化，也可以切到原始 SQL。还有子查询、把已有 SQL 导回画布、保存场景、笔记，以及多条 MySQL 连接。

### 2026-04 至 2026-10　原项目加到 1.117.0

这一段仍是 PHP 版，按能力归成几组，不逐条列出小修。

- 结果表：排序、交换列、调整列宽、搜索、行号、复制。
- 画布：同一张表可以放多次，一张图上可以有多条连线，可以复制一整组，有小地图，右键拖动可以挪动画布。
- 查询：BETWEEN、自定义表达式、时间戳转换、子查询范围高亮和重命名。
- 外部数据：载入 CSV 和 XLSX，并和查询结果比较。
- 分析：执行计划图、列分布、列血缘、结果对比。
- 记录：查询记录、分组，以及多轨时间线，时间线可以导出。
- 2026-07-04，1.86.0 加入 SQLite。
- 2026-10，固定侧栏默认打开，并加入多标签。原项目最后一条功能提交是 1.117.0，修的是右侧面板。

### 2026-10-18　Node 版，学生机上不再要 PHP

本地 `main` 上的三条提交把服务从 PHP 换成 Node，桌面窗口用 Electron。

- 画布和 SELECT 拼接留在 `node_app/`。浏览器打开 `http://127.0.0.1:4173`，或者用 Electron 窗口。连接和场景只写在本机。界面默认中文，可以切回 English。聚合和运算字段用点选拼出来。查询结果可以画成线图、柱图、排行榜、条形图、箱型图、直方图、饼图、雷达图、气泡图、漏斗图，多张图放在同一块画板上。HAVING 可以按 SELECT 里聚合别名筛选，例如 `SUM_PRICE > 600`。
- 子查询卡片自己运行时可以保留结尾分号。底部「运行查询」把它放进 `FROM ( ... )` 时去掉这个分号，避免 MySQL 在 `;)` 处报语法错误。
- 打包时写明 CPU 架构。在 Apple 芯片的 Mac 上，Mac 包同时打 arm64 和 x64，Windows 包打 x64。包没有签名。

## 运行

需要 Node.js 20 或更新版本。

```bash
cd node_app
npm install
npm start
```

浏览器打开 `http://127.0.0.1:4173`。服务只监听本机。连接、场景写在 `node_app/storage/`，这个目录不会进入 Git。

桌面窗口：

```bash
cd node_app
npm run desktop
```

安装包自己带服务，数据放在系统的用户目录里，不和浏览器版的 `storage/` 混用。

## 版本

版本号只写在 `node_app/package.json` 的 `version`。页面标题、右上角、关于窗口、保存的场景，以及安装包文件名都读这个号。当前源码版本是 1.1.3。

## 安装包

发布不在本机打包。改完版本号并推送到 GitHub 后，用**和版本号相同的标签**触发 Actions。流程文件是 `.github/workflows/release.yml`。

1. 把 `node_app/package.json` 的 `version` 改成要发布的号，例如 `1.1.1`，然后提交并推送 `main`。这一步只跑测试，不打安装包。
2. 在包含该版本号的那次提交上打标签并推送。标签必须是 `v` 加版本号：

```bash
git tag v1.1.1
git push origin v1.1.1
```

3. 打开仓库的 Actions。先是 Ubuntu 上的测试。测试通过后，macOS 运行 `npm run pack`，同时打出 Apple 芯片、Intel Mac 和 Windows x64 的包。包没有签名。
4. 打包成功后，同一个 Action 建立或更新 [Release](https://github.com/WangLaoShi/JoannaSQLBuilderGUI/releases)，并把下面四个文件挂上去。文件名里的版本号就是 `package.json` 里的号。

打包机上的文件名带空格，例如 `SQL Joiner-1.1.1-arm64.dmg`。GitHub Release 的附件名不能有空格，所以上传后空格会变成点。下载时看到的是：

| Release 上的文件 | 给谁用 |
|---|---|
| `SQL.Joiner-<版本>-arm64.dmg` | Apple 芯片的 Mac |
| `SQL.Joiner-<版本>.dmg` | Intel Mac |
| `SQL.Joiner.Setup.<版本>.exe` | Windows 安装程序 |
| `SQL.Joiner-<版本>-win.zip` | Windows 解压后直接运行 |

也可以不打标签：在 GitHub 的 Actions 页选 “Check and release”，点 “Run workflow”，勾选发布 Release。它会按当前 `main` 上的 `package.json` 建立 `v<版本>` 并挂上安装包。

标签和 `version` 不一致时，测试步骤会失败，不会去打包。普通 `git push` 不会产生 Release。`node_app/dist/` 不进 Git。

本机仍然可以打包，供自己试装。在 `node_app` 里执行 `npm run pack`。Mac 第一次打开：在 Finder 里按住 Control 再点应用，选择「打开」。Windows 若出现 SmartScreen，选择「仍要运行」。

## 界面怎么用

右上角可以在中文和 English 之间切换。SQL 关键字、表名、字段名和查询结果保持原样。

1. 点「场景」，新建一条 MySQL 连接，填写主机、端口、库名、账号和密码，测试通过后保存。SQLite 可以填一个本机数据库文件路径。
2. 在左侧选中连接，把表拖到画布上。表和表之间拖字段连线，选择 INNER、LEFT、RIGHT、FULL 或 CROSS。
3. 右侧勾选要查询的字段。每一组表是一个「岛」，可以命名、收起、改颜色。
4. 底部看生成的 SQL。点「运行查询」。结果出现在下方表格里。正在跑的查询可以停止。

LIMIT 最大 5000 行。WHERE 里写下的值会原样进入 SQL，字符串要自己加引号，例如 `'衣服'`。

## 聚合和 HAVING

求和、计数不要把字段直接拖进 SELECT。在 SELECT 底部的自定义表达式里新增一条：

- 左侧选聚合函数，右侧点字段，拼出 `SUM(p.sale_price)`。
- 别名写成 `SUM_PRICE` 这种不含空格的名字。
- 纳入方式选「和字段一起」或「只要表达式」。停在「不写入 SQL」时，这条表达式不会出现在查询里。
- GROUP BY 拖入分组字段，例如 `p.product_type`。

HAVING 是分组之后的筛选：

- 点 HAVING 下面出现的 `SUM_PRICE`，填 `> 600`。生成的是 `HAVING SUM_PRICE > 600`，表示这一类的合计大于 600。
- 要按类别名称筛选，把已经放进 GROUP BY 的字段拖进 HAVING，例如 `p.product_type = '衣服'`。
- `p.sale_price > 600` 不能放在 HAVING 里。分组之后没有单独的单价。想先丢掉便宜的行，把这个条件放进 WHERE。

也可以把 HAVING 切到原始 SQL，直接写 `SUM(p.sale_price) > 600`。

运算字段用表达式编辑器左侧的「运算」：点字段和 `+ − * /`，例如 `sale_price * 数量`。

## 子查询

左侧点「+ 子查询」，在卡片里写一条 SELECT。结尾可以留着分号：卡片上的「运行」会单独执行这段文字。底部「运行查询」把它放进 `FROM ( ... ) 别名` 时，会自动去掉结尾分号，否则 MySQL 会在 `;)` 处报语法错误。

查出的列要自己登记。在卡片的「添加连接字段」里输入列名或别名，例如 `product_type`、`sum_price`。名字必须和子查询 SELECT 里的列名或别名一致。登记之后，这些列出现在右侧，可以勾选，也可以拖到另一张表的字段上连线。

子查询没有和任何表连线时，它单独成一组。底部运行的是当前选中的那一组。

## 图表

查询有结果后点「图表」。文字列当分类，数字列当数值。列的左右顺序都可以。

可选线图、柱图、排行榜图、条形图、箱型图、直方图、饼图、雷达图、气泡图、漏斗图。选好一种后点「加入画板」，再换一种继续加入。点「图表画板」把这些图放在一起看。

箱型图和直方图看的是数字列的分布。雷达图至少要 3 个分类。饼图和漏斗图使用大于 0 的数字。气泡图有两列数字时，分别作为横轴和纵轴；有第三列数字时，用它决定气泡大小。

## 不要把它当成公开网站

现在没有登录。一台机器上的连接和已保存场景是共用的，数据库密码以明文写在本机的 `profiles.json` 里。适合老师或学生在自己的电脑上用。不要把这个服务放到公网上给不同的人一起访问。
